# 2026-11-06

## 문제와 원인

### 영구 손실 경보가 새 손실을 가렸다

커버리지 미달은 **영구 손실이라 설계상 닫히지 않는다.** 그래서 한 번 나면 그 뒤로
매일 심각이 된다. 실제로 벌어진 일은 이렇다.

```
10-17  기아 2건 발생        →  심각
10-18  ...                 →  심각  (같은 2건)
  ...                          매일 심각
10-29  기아 1건 추가        →  심각  (4건인데 겉보기는 어제와 같다)
10-30  기아 1건 추가        →  심각
11-04  내가 세어보고서야 2 → 4로 는 것을 발견
```

**새 손실 2건을 알아채는 데 엿새가 걸렸다.** 알림은 10-15에 고쳐서 매일 뜨고 있었다 —
뜨는데 **내용이 어제와 같아서** 아무도 열어보지 않은 것이다.

09-28에 "매일 울리는 심각은 아무도 안 본다"를 교훈으로 적고 장중 구멍 판정을 고쳤는데,
**바로 옆 항목이 똑같은 상태였다.**

## 결정

### 영구 손실에는 조치가 없다 — 한 번 알렸으면 조용해지는 것이 맞다

되돌릴 수 없는 일을 매일 외치는 것은 정보가 아니라 잡음이다. 그래서 **새로 난 것만
심각으로 올리고, 누적은 상태와 무관하게 늘 보여준다.**

```
NEW_LOSS_DAYS = 3        # 주말을 건너뛰어도 한 번은 보도록
```

| 상황 | 판정 |
|---|---|
| 사흘 안에 새로 난 영구 손실이 있다 | **심각** + 발생일 표시 |
| 전부 사흘 넘었다 | 경고 — `커버리지 미달 누적 4건 — 전부 사흘 넘은 것, 되돌릴 수 없다` |
| 수집 실패만 있다 | 경고 (다음 회차가 메운다) |

**조용해지는 것과 잊히는 것은 다르다.** 누적 건수는 매일 상태 줄에 남는다.

**기각한 대안**

| 대안 | 기각 사유 |
|---|---|
| `acknowledged_at` 열 추가 | 스키마 버전이 올라간다(`SCHEMA_VERSION` 불일치는 예외를 던진다). 마이그레이션 값어치가 이 문제엔 과하다 |
| 직전 점검 대비 증감 비교 | 상태 파일이 필요하고, 그 파일이 깨지면 조용히 오작동한다 |
| 그대로 두기 | 엿새 늦게 아는 것이 기본값이 된다 |

## 해결

- `scripts/health_check.py` — `check_gaps(store, now)`가 `NEW_LOSS_DAYS`로 새 것과
  묵은 것을 가른다. 새 것이 있으면 **발생일까지 찍는다**(`새 영구 손실 2건 (10-29, 10-30)`)
- 테스트 221 → 224. 그중 하나가 이 변경의 이유다 —
  `test_쌓인_것_사이에_새_손실이_섞이면_잡는다`: 묵은 4건에 오늘 1건을 섞어도
  **심각이어야 하고 누적 5건이 같이 보여야 한다**

**적용 결과**

```
전:  심각   !! 열린 gap   커버리지 미달 4건 (영구 손실)
후:  경고   !  열린 gap   커버리지 미달 누적 4건 — 전부 사흘 넘은 것, 되돌릴 수 없다
```

점검 전체가 3주 만에 **심각에서 내려왔다.** 남은 경고는 전부 되돌릴 수 있거나
이미 아는 것들이다.
