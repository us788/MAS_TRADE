전에는 한 종목이라도 성공하면(`succeeded > 0`) 그 주를 끝난 것으로 보고 건너뛰었다.
그래서 부분 실패한 주의 나머지가 재시도 없이 사라졌다.

```
09-23  23/30 (7건)   10-14  29/30 (1건)   10-28  25/30 (5건)
11-04  29/30 (1건)   11-18  13/15 (2건)        합계 16건
```

이제 `signals`에 그 시점·그 종목의 행이 있는지로 판정하고, **빠진 종목만** 돌린다.

### 재시도에는 상한 셋을 건다

그냥 열면 안 된다. 이 작업은 **네트워크 변경마다 발화한다**(실측 분당 3회).
영영 실패하는 종목 하나가 매 발화마다 LLM을 부르면 09-28에 가격 수집으로 당한 일이
그대로 반복된다.

| 상한 | 값 | 이유 |
|---|---|---|
| 시도 횟수 | 4회 | 정상은 1회. 부분 실패가 나야 2회째가 돈다 |
| 쿨다운 | 30분 | 발화 폭주에서 한도를 한 번에 태우지 않는다 |
| **지연** | **48시간** | 아래 |

판정은 **벤더도 LLM도 부르기 전에** `runs`·`signals` 테이블만 보고 끝난다.

## 사고 — 내가 오염을 만들었다

**재시도 로직을 먼저 넣고 무결성 가드를 나중에 넣는 사이에 launchd 작업이 발화해
중간 코드를 집었다.**

```
run_id 5d5cf0f9…  시작 2026-11-22T08:26:19
  └ 005930  as_of 2026-11-18  생성 2026-11-22T08:27:03   (+106시간)
  └ 000660  as_of 2026-11-18  생성 2026-11-22T08:28:03   (+106시간)
```

프로세스는 빠진 2종목만 돌고 스스로 끝났다(피해는 유한했다). 그 회차의 `notes`에
사유를 적었고 **시그널은 지우지 않았다** — 전량 로깅 원칙이고, 지우면 사고의 크기가
기록에서 사라진다.

> **교훈: 돌아가는 스케줄러 위에서 돈 쓰는 경로를 편집하지 않는다.**
> 중간 상태가 그대로 실행된다. 가드를 먼저 커밋하고 기능을 뒤에 붙이거나,
> 작업 중에는 해당 launchd 작업을 내려두고 한다. 09-28의 "값싼 판정을 앞에
> 세운다"와 같은 계열인데, 이번 것은 **"위험한 변경은 가드부터"**다.

## 그걸 거르려다 훨씬 큰 것을 건드렸다

"as_of 이후 종가가 나온 뒤 만든 시그널은 거른다"를 읽는 쪽에 넣어봤더니
**286건 중 93건(33%)이 걸렸다.** 버그가 아니었다 — `created_at`은 UTC, as_of는
KST라, **07:00 KST에 시작한 회차가 KR 장 마감(15:30)을 넘겨 끝나는 일이 흔했다.**

```
as_of → 생성 지연      중앙값 9.1h · 평균 14.7h · 최대 106.5h

1시간 이내     3건 ( 1.0%)      1~3일    24건 ( 8.4%)
1~9시간      129건 (45.1%)      3일 초과  11건 ( 3.8%)
9~24시간     119건 (41.6%)
```

**두 달 동안 아무도 몰랐던 사실이다.**

### 이것을 오염으로 보지 않기로 했다

| 각도 | 결론 |
|---|---|
| 입력 기준 | 오염 아니다. 컨텍스트가 `known_at <= as_of`로 막혀 있어 LLM은 미래를 못 본다 |
| 실행 가능성 기준 | 오염이다. 9시간 늦으면 KR 장이 닫힌 뒤고 5거래일 중 1일 결과가 정해졌다 |

**이 프로젝트가 재는 것은 실행 가능성이 아니라 구조의 판단력이다.** 그래서 표본에서
빼지 않는다. `--weekly`가 as_of를 수요일로 스냅하는 설계("늦게 깨어나도 요일은
유지된다")도 늦은 생성을 이미 허용한 결정이었다.

**대신 숫자를 늘 보이게 둔다.** `score_signals.py`가 시장마다 한 줄을 찍는다.

```
KR  생성 지연  중앙값 9.0h · 최대 106h · 24h 초과 11건(7.8%)
US  생성 지연  중앙값 9.6h · 최대  79h · 24h 초과 24건(16.6%)
```

**기각한 대안**: 엄격하게 거르면 33%를 잃는다. 지금 표본 규모에서 과하고,
무엇보다 **그 기준을 한 번도 정한 적이 없는데 소급 적용하는 것**이 옳지 않다.

> **단, 층 2(가상 포트폴리오)에는 이 결정이 그대로 적용되지 않는다.**
> `docs/baselines.md` 7.1절이 "체결은 시그널 당일 종가"를 전제하는데, 생성이 그
> 종가 뒤면 그 전제가 깨진다. 층 2 숫자를 읽을 때 같이 봐야 한다.

재시도 상한을 48시간으로 둔 근거가 이 분포다 — 꼬리 3.8%를 자르는 선이고,
**재시도는 "다시 돌릴까"를 고르는 행위라 정상 회차와 달리 상한이 필요하다.**
