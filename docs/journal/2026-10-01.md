# 2026-10-01

## 결정

### KR 벤치마크를 `KS200` → `069500`(KODEX 200)으로 바꿨다

09-28에 "며칠 기다린다"고 적었던 것을 뒤집는다. **기다림의 전제가 틀렸다.**

그때 기록한 진단은 "FDR이 한국 지수 계열에 빈 응답을 준다 (3년 구간 전체가 빈
응답)"였다. 오늘 직접 확인한 것은 다르다.

```
fdr.DataReader("KS200", "2023-10-01", "2026-09-30")   →  721행, 마지막 2026-09-17
fdr.DataReader("KS200", "2026-09-15", "2026-09-30")   →    3행, 마지막 2026-09-17
fdr.DataReader("KS11",  ...)                          →   같음, 마지막 2026-09-17
fdr.DataReader("KQ11",  ...)                          →   같음, 마지막 2026-09-17
fdr.DataReader("069500", ...)                         →  정상, 마지막 2026-09-30
fdr.DataReader("005930", ...)                         →  정상, 마지막 2026-09-30
```

앱과 같은 경로(`fetch_benchmark("KR", ...)`)로 연속 3회 불러도 매번 721봉이 온다.

- **빈 응답이 아니다. 계열 동결이다.** 세 지수가 같은 날 멈췄고 ETF·개별주는 멀쩡하다.
- 09-28에 2시간 만에 241건이 쌓인 "빈 응답"은 **간헐적 장애**였고, 하루 1회뿐인
  실제 수집이 하필 그 순간에 걸려 왔다. 그래서 동결이 빈 응답으로 기록됐다.
- **차이가 결정적이다.** 빈 응답이면 기다리면 복구되지만, 동결이면 09-18~09-29는
  기다려도 오지 않는다. 그 사이 KR 시그널 43건이 전부 `misaligned`/`stale`이었다.

**기각한 대안**

| 후보 | 기각 사유 |
|---|---|
| 계속 대기 | 동결이라 기댓값이 없다. 09-28 판단의 전제("가격은 백필된다")가 이 구간엔 성립하지 않는다 |
| `^KS11` (yfinance) | 20거래일 차이 표준편차 1.46%p — ETF의 **5배**. 우리 호라이즌이 5·20거래일이다 |
| `^KS200` (yfinance) | 과거 이력이 없다 |
| KS200만 타 소스로 백필 | "같은 시계열을 두 소스에서 받지 않는다"(`price_sources.py`) 위반 |

### ETF는 지수가 아니다 — 영향을 먼저 재고 받아들였다

`069500`은 **분배금이 반영된 계열**이다. 저장된 KS200 3년치와 겹치는 721거래일로 쟀다.

```
20거래일 수익률 차이(ETF−지수)  평균 +0.154%p  표준편차 0.314%p  n=701
전구간(2.86년)                 지수 CAGR +52.05%  ETF CAGR +55.09%
일간 수익률 차이               표준편차 0.261%p  (연율 추적오차 4.15%p)
```

**표준편차 0.314%p는 09-28에 실측한 0.31%p와 일치한다.** 반면 "계통 편차 연 −2.04%p"는
부호가 틀렸다 — ETF가 지수보다 **연 +1.95%p 더 오른다**(산술). 당시 지수−ETF로 적었거나
부호를 뒤집어 옮긴 것으로 보인다. 정정한다.

월말 비율이 분배락 톱니 없이 매끄럽게 우상향한다(100 → 105.8, 2.96년). 배당수익률
약 2.1% − 보수 0.15% ≈ +1.95%와 맞는다. **ETF 가격 계열이 분배금 조정됐다는 뜻이다.**

`docs/harness.md` 3.4.1이 "벤치마크는 배당 미포함 가격지수"를 전제로 `close_px`를
못박았는데, **KR에서 그 대칭이 깨졌다.** XOM 사례의 반대 방향이다 — 이번엔 종목이
아니라 벤치마크가 배당을 갖는다.

**그런데도 받아들인 이유**: 같은 날짜·같은 전략에서 벤치마크만 바꿔 재봤다.

```
전략                 H     KS200    069500       차이
momentum_60d       5     0.24%     0.24%  +0.000%p
momentum_60d      20     1.26%     1.26%  +0.000%p
momentum_20d       5/20  동일              +0.000%p
reversal_5d        5/20  동일              +0.000%p
low_volatility     5/20  동일              +0.000%p
ma_gap_120d        5/20  동일              +0.000%p
buy_and_hold       5    -0.38%    -0.39%  -0.015%p
buy_and_hold      20    -1.82%    -1.92%  -0.100%p
```

초과수익은 `종목 − 지수`이고 매수·매도가 섞이면 **지수항이 상쇄된다.** 횡단면
5전략은 소수점 아래까지 같고, **전량매수만 분배금만큼 불리해진다.** LLM 시그널도
buy 19 / sell 23으로 균형에 가까워 대부분 상쇄된다.

→ 즉 **판단력 측정(층 1)은 영향받지 않고, 순매수 편향 지표만 기억하면 된다.**

## 문제와 원인

### 가격 수집이 매 실행 3년 전체를 다시 요청하고 있었다

```python
return (min(start, floor) if start > floor else start), today
#       ^ start > floor 면 floor를 돌려준다 = 두 갈래 모두 min(start, floor)
```

`--dry-run`이 32종목 전부 `2023-10-01 ~ 2026-09-30`을 찍었다. `OVERLAP_DAYS = 5`도
"마지막 봉 근처부터 이어받는다"는 docstring도 **사문이었다.** 의도는 `max`다.
09-28에 2시간 만에 벤더 호출이 수천 건 난 원인 중 하나다(발화 빈도가 다른 하나).

### `docs/baselines.md`의 주 표가 재현 불가 상태였다

3.2·3.3절의 t값 표(겹침 보정)를 내는 코드가 **저장소에 없었다.** 09-16 측정 때
세션에서 일회성으로 돌아갔고, 6절 "재현" 명령은 명목 표만 낸다. 벤치마크를 바꿔
숫자를 다시 내려는 순간 드러났다.

### KR 가격의 변동성이 US의 2.5배다 (문제 아님 — 확인만)

지수 교체 과정에서 눈에 띄어 확인했다. **데이터 오류가 아니라고 판단한다.**

## 미결

- **뉴스 gap을 닫는 경로가 고장나 있다** (09-30 확인, 미수정). 구멍을 실제로 메운
  회차가 `reached_floor=0`이라는 이유로 공적을 인정받지 못하고(`collector.py:144`),
  그 회차가 lookback 시계를 전진시켜 이후 영원히 닫히지 않는다. `--resolve-gaps`도
  `reached_floor=1`을 요구해 0건을 돌려준다(`storage.py:343`).
  09-22 gap 4건은 **직전 회차 커버리지와 겹치므로 실제 손실이 아니다** — 즉
  health_check의 "영구 손실 2건"은 거짓 경보고, 그것 하나가 매일 전체를 심각으로 칠한다
- **가격 gap은 자동 해소 경로가 아예 없다.** `prices.py:425`의 `resolve_gap`은
  테스트만 부른다. 오늘 KS200 247건은 손으로 닫았고, 남은 10건(이미 복구된 일시 실패)은
  일부러 남겼다 — 자동 해소를 만들 때 그 판정 규칙으로 닫아야 한다
- **KR 층 2는 비대칭 비교다.** 포트폴리오는 배당 없는 KR 종목(`close_tr == close_px`),
  벤치마크는 분배금 있는 ETF. 연 약 2%p 불리하다. 층 1은 상쇄되므로 영향 없다
- **FDR 한국 지수 계열이 돌아오는지 본다.** 돌아와도 되돌리지 않는다 —
  **교체 전후 성적을 섞지 않는다**(기획서 7절). 되돌릴 거면 그때 다시 재계산해야 한다
- 벤더 일시 실패가 상시화됐다(yfinance 빈 응답 GOOGL·UNH·META·CAT·XOM,
  FDR 커넥션 리셋 000270·105560). 재시도로 전부 복구돼 봉 수는 정상이다. 빈도만 기록해 둔다
- **09-30 베이스라인은 30/30으로 끝났다.** 다만 같은 as_of로 `0/15`가 두 번 먼저
  찍혔다(`APIConnectionError`). 네트워크 트리거가 DeepSeek 연결 준비 전에 발화한다.
  전건 실패라 가드에 안 걸려 재시도가 성공했을 뿐이다 — **1건이라도 성공했으면
  09-23처럼 부분 성공으로 닫혔다**
