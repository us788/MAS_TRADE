# 작업 일지

날짜별로 **무엇을 정했고, 무엇이 막혔고, 왜 그랬는지**를 남긴다.
`docs/journal/YYYY-MM-DD.md` 한 파일이 하루다.

## 왜 쓰는가

이 프로젝트는 3개월 이상 돌려야 결론이 나온다. 그때가 되면 "왜 이렇게 만들었더라"를
코드만 보고 복원할 수 없다. 특히 두 가지가 기록되지 않으면 반복해서 손해를 본다.

- **기각한 선택지.** Alpha Vantage를 뉴스 메인에서 뺀 이유를 잊으면 반년 뒤에 또 검토한다.
- **미해결 문제의 가설과 반증.** 어디까지 확인했는지가 없으면 처음부터 다시 판다.

## 형식

네 덩어리. 없는 항목은 비운다.

```markdown
# 2026-09-15

## 결정
- 무엇을 정했는지와 **왜**. 기각한 대안과 기각 사유를 같이 적는다.

## 문제와 원인
- 증상 → 확인한 사실 → 원인(모르면 "미상"). 가설은 가설이라고 적는다.

## 해결
- 무엇을 어떻게 고쳤는지. 커밋 해시를 남긴다.

## 미결
- 다음에 이어서 볼 것. 어디까지 확인했는지를 함께.
```

## 규칙

- **원인을 모른 채로도 남긴다.** 해결된 것만 적으면 일지가 아니라 홍보물이 된다.
- **틀린 판단은 지우지 않고 정정으로 남긴다.** 왜 틀렸는지가 다음 판단의 재료다.
- **추측과 확인된 사실을 구분해 적는다.** "~로 보인다"와 "~를 확인했다"를 섞지 않는다.
- 숫자(한도·단가·순위)는 **확인한 날짜**를 함께 적는다. 벤더가 바꾼다.
- 기획서(`plan.md`)는 **현재 상태**를, 일지는 **거기까지 온 경로**를 담는다.
  결정이 확정되면 기획서에 반영하고, 일지에는 그 결정의 근거를 남긴다.
