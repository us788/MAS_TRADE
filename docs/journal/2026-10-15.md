# 2026-10-15

## 확인

### 10-14 주간 베이스라인이 **사람 손 없이** 돌았다

10-07에 넣은 수리(DNS 외부 제한 + 래퍼 워치독)를 실전에서 확인하는 것이 이번 주의
항목이었다. 지난주처럼 멈춘 래퍼가 슬롯을 무는 일은 **재발하지 않았다.**

```
US 2026-10-14T07:00  15/15
KR 2026-10-14T07:00  14/15   실패: 000660 APITimeoutError
```

다만 **수리가 통했다는 증거는 아니다.** 워치독은 한 번도 발화하지 않았고(`ABORT` 0건)
`nslookup` 강제 종료도 0건이다. **멈출 일이 없었을 뿐**이고, 워치독 자체는 격리
테스트 말고는 아직 검증되지 않았다.

## 문제와 원인

### macOS 알림이 한 번도 작동한 적이 없다

점검 로그를 보다 매 회차 맨 앞에 찍힌 줄을 발견했다.

```
23:24: syntax error: “"”을(를) 예상했지만 알 수 없는 토큰을(를) 발견했습니다. (-2741)
```

- **확인한 사실**: `json.dumps(body)`가 기본값(`ensure_ascii=True`)으로 한글을
  `\uXXXX`로 이스케이프하는데 **AppleScript는 `\u`를 모른다.** 에러 위치 23:24가
  정확히 `display notification "` 바로 뒤, `\u`가 시작되는 자리다.

```
현재                 "한국 장중 ...   →  syntax error (-2741)
ensure_ascii=False   "한국 장중 커버리지: 3시간 ..."   →  성공
```

- **범위**: 점검 항목 이름이 전부 한글이므로 **이상이 있을 때마다 100% 실패했다.**
  2026-09-17부터 22번 전부. `check=False`라 조용히 넘어가고 에러는 `health.log`에만
  남았다.
- **처음엔 로케일을 의심했다.** launchd 환경에 `LANG`이 없어 osascript가 UTF-8을
  잘못 읽는다는 가설이었는데, `env -u LANG` 으로 돌려보니 **그냥 성공했다.** 기각.

> **조용히 죽는 것을 잡으려고 만든 장치가 조용히 죽어 있었다.**
> 이번 달에만 세 번째다 — 종료코드 0(10-07), 창 경계(10-08), 그리고 이것.
> 셋 다 "경보가 안 울린다"가 아니라 **"경보가 울렸는데 아무도 못 받는다"**였다.

### KR 회차가 7시간 51분 걸렸는데 3시간 워치독이 안 끊었다

```
KR  2026-10-13T22:46:18Z → 2026-10-14T06:37:05Z   7시간 51분   (지난주 59분)
US  06:37:05 → 06:52:52                            16분
```

- **가설(미확인)**: `sleep`은 맥이 자는 동안 안 흘러간다. 그렇다면 워치독은
  **벽시계가 아니라 깨어 있던 시간**을 센다 — 멈춘 프로세스도 3시간을 *깨어서*
  버텨야 끊긴다. 09-23에 관찰한 DarkWake 프리즈/재개 패턴과 모양이 같다.
- **확인하지 못한 것**: 실제로 `sleep`이 시스템 잠자기 중 멈추는지 재보지 않았다.
  맥을 재워야 재현된다.
- **같이 걸리는 문제**: `check_scheduler`는 `ps -o etime`(**벽시계**)으로 4시간을
  본다. **둘이 서로 다른 시계를 쓴다.** 이번처럼 7시간 51분 걸린 **정상** 회차가
  도는 중에 점검이 겹쳤으면 심각 오보가 났을 것이다. 이번엔 점검이 시작 전(00:07)과
  종료 후(다음날 00:04)에 돌아 **우연히** 안 걸렸다.

## 해결

- `health_check.py` — `_notification_script()`로 분리하고 `ensure_ascii=False`.
  회귀 테스트 둘(`\u`가 없을 것 · 따옴표는 이스케이프될 것). 테스트 213 → 215
- 워치독 시계 불일치는 **고치지 않았다.** 미결에만 남긴다(아래)

## 미결

- **워치독(깨어 있던 시간)과 점검(벽시계)이 다른 시계를 쓴다.** 셋 중 하나를 골라야
  한다 — ① 점검도 깨어 있던 시간으로 보거나 ② 워치독을 벽시계(종료 시각을 파일에
  적고 비교)로 바꾸거나 ③ 노트북에서는 못 맞춘다고 보고 상시 전원 기기로 미룬다.
  **지금은 오보도 미탐도 실제로 난 적이 없다** — 우연히 안 겹쳤을 뿐이라는 것만 기록해 둔다
- **29/30이다.** 000660이 타임아웃으로 날아갔고 가드가 `succeeded > 0`을 완료로 보므로
  재시도되지 않는다. 미결 "부분 성공이 완료로 기록된다" 그대로이고, 10-14 000660
  시그널은 영구 손실이다
- **워치독은 실전에서 발화한 적이 없다.** 격리 테스트만 통과했다. 다음에 실제로
  멈추는 일이 생겨야 검증된다
