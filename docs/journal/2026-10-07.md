# 2026-10-07

## 문제와 원인

### 주간 베이스라인이 7일째 죽어 있었다 — `nslookup`이 안 끝났다

오늘이 수요일인데 18:09에 `--check-due`가 KR·US 둘 다 남았다고 했다. `baseline.log`는
**09-30 17:51 이후 한 줄도 안 늘었고**, 그때 생긴 `.baseline.lock`이 그대로였다.

```
pid 1681  /bin/bash run_baseline.sh                        경과 07-00:18:36
pid 1694  └─ /usr/bin/nslookup -timeout=3 api.deepseek.com  경과 07-00:18:36
```

- **확인한 사실**: `-timeout=3`은 **DNS 응답 대기만** 제한한다. 총 실행시간은 제한하지
  않는다. 그 nslookup이 7일을 넘겨 살아 있었다.
- **연쇄**: launchd가 그 작업을 `state = running`으로 본다 → **같은 작업의 새
  인스턴스를 띄우지 않는다** → 10-07 07:00 캘린더 발화도, 네트워크 변경 발화도
  전부 무시 → 2시간 stale 락 회수는 **새 프로세스가 떠야 도는 로직**이라 영원히
  돌지 않는다.
- **발단**: 09-30 회차는 30/30으로 성공했다. 그 **직후 잉여 발화**가 하나 더 떴고
  (`pid 1681`), 그게 물렸다. **성공한 회차가 다음 회차를 죽였다.**
- 멈춘 지점이 하필 **가장 값싼 판정**이었다. 09-28에 "값싼 판정을 항상 앞에 세운다"를
  교훈으로 적었는데, 그 앞에 더 값싼 것이 있고 **그게 멈출 수 있다**는 건 못 봤다.

### 왜 두 주 동안 아무도 몰랐나

| 장치 | 왜 못 잡았나 |
|---|---|
| `check_scheduler` | **`last exit code`만 본다.** 이전 인스턴스가 남긴 0이 그대로 "정상"으로 읽혔다 |
| `check_baseline` | `BASELINE_MAX_DAYS = 8`이고 **경고까지만** 간다. 7.1일인 그 시점에도 OK였다 |

**종료코드 0은 "지금 잘 돌고 있다"가 아니다.** 09-28에 "안전장치의 종료코드를 그대로
게이트로 쓰지 마라"를 적었는데, 이번엔 같은 값을 **모니터링**에 쓰고 있었다.

## 해결

멈춘 프로세스를 죽이자 **launchd가 3초 만에 새 인스턴스를 띄웠다**(pid 60004).
이번엔 DNS를 통과했고 가격 32/32 → 신선도 OK → 시그널로 이어졌다.
`--weekly`가 as_of를 직전 수요일로 스냅하므로 **2026-10-07T07:00 표본으로 기록됐다.**

```
US 2026-10-07T07:00  15/15      KR 2026-10-07T07:00  15/15
```

### 코드

- **`wait_for_dns`를 외부에서 끊는다** — `probe_dns()`가 nslookup을 백그라운드로
  띄우고 20초 안에 안 끝나면 죽인다. macOS에는 `timeout(1)`이 없다.
  **래퍼 셋 전부에 있었다** — `run_collect.sh`에도 같은 코드가 있었고,
  **거기서 물렸으면 뉴스는 영구 손실이다.**
- **래퍼 자체 워치독** — baseline 3시간, collect·prices 30분. 멈춘 래퍼 하나가
  launchd 슬롯을 물면 그 작업은 다시 뜨지 못한다.
- `check_scheduler`가 `ps -o etime`으로 **실행 시간**을 보고 4시간 넘으면 심각.
  macOS ps에 초 단위 `etimes`가 없어 파서를 따로 뒀다.
- `check_baseline`을 경고 → **심각**으로. 놓친 주의 표본은 as_of가 고정 요일에
  묶여 있어 다음 주에 두 번 낼 수 없다.
- 실행 중인 작업에는 `last exit code`가 없는데 그걸 `?`로 읽어 경고를 띄우고 있었다
  (기존 코드도 동일). 제거했다.

### 워치독을 두 번 틀렸고 두 번 다 격리 테스트로 잡았다

**써놓고 돌려보지 않았으면 그대로 커밋됐을 것들이다.**

1. `pkill -9 -P "$$"`가 **자기 자신**(워치독 서브셸)도 자식이라 먼저 죽었다.
   `kill -9 "$$"`에 도달하지 못한다 — 워치독이 아무것도 안 한다.
2. 래퍼만 죽이면 **python·caffeinate가 고아로 살아남았다**(실측).

→ launchd가 띄우면 래퍼가 프로세스 그룹 리더다(실측 `PGID == PID`). 그룹째 끊고,
손으로 돌린 경우엔 `kill_tree`로 트리를 훑는다.

## 미결

- **배터리 + 뚜껑 닫힘은 여전히 안 풀린다.** 워치독은 멈춘 작업이 슬롯을 영원히 무는
  것을 막을 뿐이고, DarkWake 재취침 자체는 상시 전원 기기로 옮겨야 풀린다
- `run_prices.sh`에는 락이 없다 — 워치독이 유일한 보호 장치다. 락을 둘지 정하지 않았다
- 워치독이 SIGKILL이라 EXIT 트랩이 안 돌고 락이 남는다. 다음 회차가 stale로
  회수하지만, **회수까지 한 주기가 빈다**
