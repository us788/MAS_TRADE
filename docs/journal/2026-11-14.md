## 결정 (같은 날, 이어서) — 적응형 수집 주기를 넣었다

되돌리고 나서 **"포스트시즌만의 문제가 아니다"**는 지적을 받았다. 맞다 —
정규시즌이 4~10월로 1년의 7개월이고, 축구·다른 종목 스폰서명도 같은 구조다.
그래서 **검색어를 좁히는 쪽**을 다시 검토했다.

### 검색어 좁히기는 결론이 났다 — 안 된다

**연산자 전수 확인**

```
기아                 total 1,963,326   야구   1%
기아 -타이거즈          total    57,357   야구 100%   ← 제외가 아니다
기아 !타이거즈          total    57,357   야구 100%
기아 -"타이거즈"        total         0            ← 0건
기아 NOT 타이거즈       total        93   야구  93%
기아 +자동차           total   421,366   야구   0%   ← +(AND)만 작동
```

**실제 재현율** — 이번엔 저장된 발췌가 아니라 **라이브 색인 대비**로 쟀다.
비시즌이라 ground truth가 깨끗한 지금이 재기 가장 좋은 때였다.

```
ground truth  '기아'  최근 36시간 회사 1차자료 53건

기아 +자동차    3.8%        기아차       3.8%
기아 +주가      5.7%        기아 +차     13.2%
기아 +현대차   35.8%
```

**10-25에 "최소 절반 잃는다"고 적은 것은 하한이었고, 실제는 64~96% 손실이다.**
그때 "실제값은 더 높겠지만 잴 방법이 없다"고 썼는데 **더 높기는커녕 열 배 낮다.**
정정한다. 놓치는 기사가 전부 핵심이다 — `인도 제2공장 2.6조원 투자`,
`셀토스 누적 판매 70만 대`, `기아 94,300원 장중 흐름`.

**야구 20%를 막으려고 회사 기사 90%를 버리는 거래다.** 이 길은 닫혔다.

### 그래서 수집기가 스스로 조절한다

신호는 이미 있었다. 상한에 걸린 회차가 `reached_floor=0`으로 남고, 그 회차의
`pages`와 `oldest_seen`이 **버스트가 오는 순간의 유입 속도**를 알려준다.
한 시점에 재는 `measure_news_rate.py`와 결정적으로 다른 점이다.

```
관측 속도 = pages × 100 / (ran_at − oldest_seen)
감당 주기 = 250 / (속도 × 1.5)          ← lookback이 주기의 1.5배다
```

`fetched`가 아니라 **`pages × 100`(원본)으로 센다.** 예산을 태우는 것은 제외 규칙이
버린 기사까지 포함한 원본이다 — 10-29에 1,000건 중 38건만 남았다.

실제 이력으로 검증했다.

```
10-29 13:16  10페이지가 2.07시간  →  484건/h  →  6h에서 1h로
10-18 12:20  10페이지가 6.81시간  →  147건/h  →  6h에서 1h로
```

**10-31에 사람이 손으로 내린 것과 같은 답이다.**

### 되돌리기도 자동이다

상한 이력은 **48시간만** 본다. 버스트가 지나면 설정 주기로 저절로 돌아간다 —
오늘 사람이 한 일을 다음부터는 안 해도 된다. 지금 KR 15종목 전부 설정값 그대로다
(최근 48시간에 상한 이력 없음).

**좁히기만 하고 늘리지는 않는다.** 늘리면 사람이 정한 커버리지 의도를 뒤집는다.

### 테스트가 버그를 하나 잡았다

처음 쓴 티어 선택이 `next(t for t in TIERS if t <= capacity)`였다. `TIERS`가
오름차순이라 **감당 가능한 가장 짧은 것**, 즉 항상 1시간을 골랐다. 느린 종목까지
1시간으로 끌어내려 호출만 늘고 커버리지는 그대로였을 것이다.
`test_설정보다_늘리지는_않는다`가 바로 걸러냈다. `max(...)`로 고쳤다.

등급 정의는 `COLLECT_TIERS` 한 곳으로 모으고 `measure_news_rate.py`가 가져다 쓴다 —
둘이 어긋나면 주기가 오락가락한다.

## 미결 (추가)

- **`measure_news_rate.assign_tier`는 lookback 1.5배를 안 본다.** 감당 주기를
  `BUDGET / rate`로 계산하는데, 실제로 받는 구간은 주기의 1.5배다. 적응형 쪽은
  `BUDGET / (rate × 1.5)`로 계산한다. **같은 입력에 두 값이 1.5배 차이 난다** —
  measure 쪽이 느슨하다. 고치면 몇 종목의 주기가 짧아지므로 따로 판단한다
- 적응은 **좁히는 쪽만** 자동이다. 설정값 자체를 올려야 하는 추세 변화는
  여전히 `measure_news_rate.py --apply --allow-longer`를 사람이 돌려야 한다
