## 1순위 — 노이즈 바닥 측정 (하루 · 약 $2)

`docs/validation.md` 5.1절. **모든 A/B의 선행 조건이다.**

같은 구성을 여러 번 실행해 `Var(A−B)`의 **순수 잡음 수준**을 먼저 잰다.
`temperature=0`이어도 결정론이 아니다. 이걸 모르면 "구성 A가 B보다 낫다"가
실재인지 판정할 수 없고, **잡음을 실력으로 읽는다.**

기획서 6절의 "3회 이상 반복해 평균이 아니라 분산까지 본다"가 이것이다.

> 착수 전 확인: 같은 `as_of`로 반복 실행하면 `has_successful_run` 가드에 막힌다.
> 반복 실행 경로를 어떻게 열지(예: `kind`에 시드를 붙인다)부터 정해야 한다.

## 2순위 — 유니버스 확대

`docs/validation.md` 2·3절. **단일 최대 레버리지다.**

```
한 시점 IC의 표준오차 = 1/√(N-1)
   N=15 (지금)  →  0.267   ← 잡으려는 신호가 0.05다. 신호 대 잡음비 1:5
   N=300        →  0.058   ← 5시점이면 검출된다
```

> **3개월 × 300종목 > 2.2년 × 15종목.**

- 전진 검증이라 **생존 편향이 없다** (과거 백테스트를 접었으므로)
- 자원도 여유가 있다 (뉴스 5,300/25,000, flash 스크리닝 회당 $0.8)
- **선행 조건은 둘**: ① 전 종목 스크리닝 점수 저장(3.3절) ② 최소 거래대금 필터
  — 소형주가 들어오면 시장충격·유동성이 실재한다 (`validation.md` 7절)
- **유니버스를 바꾸면 기존 시그널과 비교가 끊긴다. 지금이 가장 싸다** (83건뿐)

## 09-28에 배운 것 — 여전히 유효하다

### 스케줄 작업에 비싼 단계를 앞에 두지 마라

시그널 기준가를 최신으로 맞추려고 `run_baseline.sh` 앞에 가격 수집을 넣었다.
그런데 baseline 작업은 **네트워크 변경마다 발화한다 — 실측 분당 3회다.**
주간 가드("이미 돌렸습니다")는 그 **뒤**에 있었다.

```
2시간 만에  벤더 호출 수천 건 · price_gaps 241건 · yfinance가 UNH·XOM을 거절
```

**고쳤다**: `run_baseline.py --check-due`가 벤더도 LLM도 부르지 않고 "이번 주 남은
시장이 있나"만 판정한다. 래퍼가 그걸 먼저 묻는다.

> **교훈: 값싼 판정을 항상 앞에 세운다.** 발화가 잦은 트리거에서는 "할 일이 없다"를
> 확인하는 비용이 0에 가까워야 한다.

### 안전장치의 종료코드를 그대로 게이트로 쓰지 마라

처음엔 `collect_prices.py`의 종료코드로 베이스라인을 막게 짰다. 지수 하나가
실패해도 종료코드는 1이다 → **FDR 장애가 계속되는 동안 주간 베이스라인이 영원히
스킵됐을 것이다.** `--check-fresh`가 **종목 봉만** 보고 따로 판정하게 바꿨다.

```
지수가 막혔다  →  채점만 미뤄진다 (백필 가능)        →  시그널은 낸다
종목이 묵었다  →  오염된 시그널이 나온다 (복구 불가)  →  시그널을 내지 않는다
```

### 등호로 0을 재지 마라

`stdev([0.1, 0.1, 0.1])`은 0이 아니라 **1.7e-17**이다. `sd == 0` 가드를 통과해
DSR이 "엣지가 있을 확률 99.98%"를 돌려줬다. 같은 함수에 `0.01`을 세 번 넣으면
정확히 0이 나와서 **기존 테스트는 통과하고 있었다** — 입력값에 따라 갈리는 가드였다.
`ZERO_VARIANCE_TOL = 1e-12`로 통일했다.

09-18에 가격 수정 이력에서 배운 것과 같은 교훈이다. 그때는 `1e-9`가 너무 빡빡해
4,744건이 잡음으로 기록됐고, 이번엔 `== 0`이 너무 느슨해 잡음이 통과했다.

### 거짓 경보는 진짜 경보를 죽인다

장중 구멍 판정을 두 번 고쳤다 — **진행 중인 시간을 빼고**, **연속 2시간 이상만**
심각으로 올린다. 수집기가 "받을 게 없다"고 건너뛴 한 시간은 손실이 아니다.
매일 울리는 심각은 아무도 안 본다.

## 건드리기 전에 알아야 할 설계 결정

근거는 `docs/journal/`에 있다. **모르고 뒤집으면 데이터가 망가진다.**

| 결정 | 이유 |
|---|---|
| `INSERT OR IGNORE` (REPLACE 아님) | `collected_at`이 최초 관측 시각으로 고정돼야 `known_at`의 보수적 판정이 유지된다 |
| as-of 필터는 항상 `known_at` | `published_at`으로 거르면 벤더 시각이 깨졌을 때 룩어헤드가 샌다 |
| 실패한 수집은 `collection_runs`에 안 남긴다 | 남기면 "방금 돌았다"로 판정돼 다음 주기까지 재시도하지 않는다 |
| `forward_bar`는 `Scorer`만 부른다 | 에이전트 코드가 미래 봉에 닿을 경로를 구조적으로 끊는다 |
| 초과수익은 `close_px`로 계산 | `close_tr`을 쓰면 배당주가 공짜 알파를 얻는다 (XOM 3년 14.9%p 차이) |
| KR 벤치마크는 `069500` (지수 아님) | FDR 지수 계열이 2026-09-18 동결. **분배금 포함이라 연 +1.95%p 높다** — 순매수 편향 지표만 영향받는다 |
| 벤치마크 심볼은 `BENCHMARKS` 한 곳에만 | 채점·컨텍스트·전략·포트폴리오·health_check가 전부 이 상수를 본다. 테스트에도 박지 않는다 |
| `drop_unclosed` — 미완결 봉은 저장 안 한다 | 장중 스냅샷이 종가로 굳으면 "벤더 오류→보류" 안전장치가 **올바른 정정을 거부한다** |
| `PRICE_REL_TOL = 1e-6` | `1e-9`는 부동소수점 잡음 4,744건을 수정 이력으로 기록했다 |
| `clean_text`는 멱등이 아니다 | 저장된 텍스트에 다시 적용하면 내용이 깎인다. `renormalize()`를 쓴다 |
| 정기 실행은 cron이 아니라 launchd | cron은 자는 사이의 실행을 건너뛰고 따라잡지 않는다 |
| 저장소는 Desktop/Documents/Downloads 밖 | TCC가 LaunchAgent 실행을 거부한다 (`exit 126` — 2026-09-16 실측) |
| 파괴적 스크립트는 dry-run이 기본 | `reclassify.py`의 잘못된 규칙이 5,009건에 적용되기 전에 잡혔다 |
