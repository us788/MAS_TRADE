# 검증 설계 — AI 퀀트 시스템

`docs/masking-test.md`를 **대체한다.** 그 문서는 "과거 데이터로 빨리 검증하자"는 전제
위에 쓰였는데, 검토 결과 그 전제가 틀렸다. 기각 근거는 4절에 남긴다.

---

## 0. 무엇을 만드는가 — 측정 대상을 못박는다

**로보어드바이저도 자산배분 시스템도 아니다.**

> **멀티에이전트 LLM으로 만드는 AI 퀀트 시스템.**

이 구분이 검증 방법 전체를 결정한다.

| | 자산배분 / 로보어드바이저 | **AI 퀀트 (이 프로젝트)** |
|---|---|---|
| 푸는 문제 | **적합성(suitability)** — 이 고객에게 맞는가 | **알파** — 시장을 이기는 신호가 있는가 |
| 정답을 정하는 것 | 고객의 재무상태·위험성향 | 실현 수익률 |
| 판단 단위 | 자산군 비중 | **종목별 방향·확신도** |
| 규제 틀 | 투자일임, 코스콤 테스트베드, 1년 6개월 공시요건 | 해당 없음 (시그널 기록만, `RUN_MODE=paper`) |
| 표준 지표 | 위험등급별 적합성·분산 | **IC / ICIR** |

코스콤 테스트베드를 최종 비교군으로 적겠다고 했던 것도 **철회한다.** 그쪽 심사 항목은
"투자자 성향 반영·분산투자 구조"이고, 우리가 만드는 것과 평가 축이 다르다.

---

## 1. 주 지표는 IC / ICIR이다

**IC(Information Coefficient)** = 매 시점 **예측 순위 vs 실현 초과수익 순위**의
횡단면 순위상관. 그 시계열의 평균이 IC, `평균/표준편차 × √주기`가 **ICIR**이다.

기획서 9.1절이 "가장 중요한 지표"로 꼽은 **확신도-수익 상관이 사실상 IC다.**
이름을 몰랐을 뿐 이미 재고 있었다. 이제 퀀트 표준 정의로 통일한다.

### 1.1 실측 (룰 베이스라인, 3년, 20거래일)

```
KR  momentum_60d   IC +0.035   t=+1.09    ICIR +0.74
KR  reversal_5d    IC -0.049   t=-1.52    ICIR -1.03
US  momentum_60d   IC -0.094   t=-2.80    ICIR -1.90
US  reversal_5d    IC +0.094   t=+3.13    ICIR +2.13   <- 실전급
```

업계 통념: **IC 0.02~0.05면 쓸 만한 팩터, 0.10이면 매우 강함.**

이 기준이 중요하다. 앞선 검토에서 나는 ρ=0.2~0.3을 목표로 표본 수를 계산했는데,
**퀀트 기준으로 비현실적으로 높은 값**이었다. 목표를 IC 0.03~0.05로 잡으면
필요 표본과 설계가 전부 달라진다.

### 1.2 왜 IC인가

- **횡단면 지표다.** 시장 전체가 오르내린 효과가 순위 계산에서 자동 제거된다
- **종목 수가 곧 정밀도다.** 시간축이 아니라 폭으로 표본을 번다 (2절)
- 팩터 업계 표준이라 외부 수치와 비교 가능하다

보조 지표는 기존대로 — 방향 적중률, 층 2 위험조정수익(`docs/baselines.md` 7절).

## 2. 병목은 기간이 아니라 **유니버스 크기**다

한 시점 IC의 표준오차는 `1/√(N-1)`이다.

| 종목 수 N | 1회 IC 오차 | IC=0.05 검출에 필요한 시점 수 |
|---|---|---|
| **15 (현재)** | **0.267** | 114회 — 주1회 **2.2년** |
| 30 | 0.186 | 55회 — 1.1년 |
| 60 | 0.130 | 27회 — 0.5년 |
| 100 | 0.101 | 16회 — 0.3년 |
| 300 | 0.058 | **5회 — 0.1년** |

**지금은 자가 너무 굵다.** 15종목이면 한 시점 IC의 잡음이 ±0.267인데 잡으려는 신호가
0.05다. 신호 대 잡음비 1:5다. KR 모멘텀이 IC +0.035인데도 t=1.09로 안 잡히는 것은
실력이 없어서가 아니라 **측정 정밀도가 모자라서**다.

```
시간 늘리기  →  √T 로만 개선
종목 늘리기  →  √N 로 개선되고, 시간과 곱해진다
```

> **3개월 × 300종목이 2.2년 × 15종목보다 낫다.**

그리고 **전진 검증에서 유니버스를 늘리면 생존 편향이 없다.** 오늘 상장된 종목으로
오늘부터 쌓으므로, 과거 백테스트를 괴롭히던 문제가 발생하지 않는다.

## 3. 유니버스 확대 설계

기획서 14.1절이 "3개월 이후 과제"로 미뤄뒀다. **앞당긴다.** 퀀트 시스템이 목표라면
이것이 단일 최대 레버리지다.

### 3.1 자원은 여유가 있다 (2026-09-16 실측)

| 자원 | 전체 시장 2,763종목 소요 | 한도 |
|---|---|---|
| 뉴스 (네이버) | 계층화 시 약 5,300/일 | 25,000/일 |
| LLM 1차 스크리닝 (`flash`) | 회당 약 $0.8 | — |
| LLM 심층 (상위 후보, `v4-pro`) | 회당 약 $0.5 | — |
| 가격 저장 | 약 200MB | 디스크 여유 24GB |

### 3.2 선행 조건 — 이제 둘뿐이다

| 조건 | 상태 |
|---|---|
| ~~시점 기준 구성종목 (생존 편향)~~ | **전진 검증이면 해당 없음** |
| **전 종목 점수 저장** | 필요. 3.3절 |
| 유니버스 변경 시 비교 단절 | 지금이 가장 싸다 (시그널 30건뿐) |

### 3.3 선택 편향 — 점수를 방향 없이 저장한다

2,763종목에서 상위 N개만 골라 시그널을 내면 **고른 것만 채점된다.** 그러면
"고른 것의 수익"만 알고 **"고른 것과 안 고른 것의 차이"**를 모른다. 후자가
스크리너의 실제 성능이고, **IC 계산에 전 종목 점수가 필요하다.**

→ `signals` 옆에 **방향 없는 스크리닝 점수**를 전 종목에 대해 저장하는 경로를 만든다.
LLM 호출은 `flash` 1차 스크리닝 한 번이므로 비용이 늘지 않는다.

### 3.4 단계

```
1  계층화 수집      대형 조밀 · 중형 중간 · 소형 일 1회 (collect_every_hours 확장)
2  1차 스크리닝     flash non-thinking · 전 종목 · 점수만 저장
3  심층 분석        v4-pro thinking · 상위 후보만 · 방향·확신도
4  IC 계산          전 종목 점수 기준. 심층 대상은 부분집합
```

기획서 8절의 "저가 모델 1차 스크리닝 → 상위 후보만 고성능 모델"이 이미 이 구조다.

## 4. 검토했다가 기각한 경로

**같은 검토를 반복하지 않으려고 근거와 함께 남긴다.**

### 4.1 과거 뉴스를 사서 1년 백테스트 — 기각

빅카인즈는 본문 200자까지만 주고, 그 이상은 **뉴스토어**(언론진흥재단)에서 산다.

```
분석용 뉴스데이터 (본문 200자)   비영리 12,397~17,710원/월   ★ 인공지능 활용 목적 불가
분석용 (Full text)              비영리 53,900~77,000원/월    ★ 동일
AI·상업 허용 뉴스데이터           1개 매체 330만원/월 ~ 51개 이상 990만원/월
```

**우리 용도가 정확히 "AI 활용"이라 싼 상품은 약관상 못 쓴다.** 쓸 수 있는 상품은
최소 구성도 월 330만 원이고, 같은 돈이면 전진 실험을 수십 아암으로 1년 내내 돌린다.

그리고 **샀어도 1년으로는 성능 검증이 안 된다** (실측):

| | |
|---|---|
| 검정력 | 20거래일 유효 표본 KR 37건 · US 107건 — 주 지표가 미달 |
| 학습 룩어헤드 | 대리기준(2026-04-24) 이후 깨끗한 구간이 38%뿐. 그것만 쓰면 KR 5일도 57건 |
| **레짐** | **1년에 2종뿐.** KR 하락 8회, **US 하락 0회.** 하락장 검증 불가 |
| 입력 불일치 | 뉴스토어는 매체 기반 아카이브라 네이버 키워드 검색과 선별 방식이 다르다 |

**상대 비교(A vs B)에는 유효하지만 절대 성능 검증은 안 된다.**

### 4.2 자산배분 트랙으로 우회 — 기각

자산군 ETF는 21~34년 이력이 있고 매크로·FOMC 성명문까지 전부 무료라, 백테스트가
실제로 가능하다. 그래서 "구조를 먼저 검증하자"고 제안했다.

**기각 사유: 문제가 다르다.** 자산배분은 고객의 재무상태·위험성향이 정답을 정하는
적합성 문제이고, 우리가 만드는 것은 알파 문제다. "자산배분에서 작동한 구조가 종목
선택에서도 작동한다"는 전이 가정이 근거 없다.

*(다만 매크로·FOMC 데이터가 전부 무료라는 사실은 유효하다. 거시 에이전트를 붙일 때
쓴다 — ALFRED vintage 동작 확인됨, FOMC 성명문 HTML 접근 확인됨.)*

### 4.3 1거래일 호라이즌으로 표본 5배 — 기각

"호라이즌을 시그널 간격에 맞추면 겹치지 않는다"는 것 자체는 맞다. 그러나 실측 결과
**호라이즌은 자유 파라미터가 아니다.**

```
1일 vs 20일 전략 순위상관   KR +0.60   US +0.30
US ma_gap_120d             1일 2위  →  20일 5위(꼴찌)
```

**1일에서 이긴 구성이 20일에서 이긴다는 보장이 없다.** 표본을 늘린 게 아니라
다른 문제를 푼 것이다.

### 4.4 마스킹 테스트 — 격하 (폐기 아님)

`docs/masking-test.md`는 "과거 백테스트를 해석할 근거를 만든다"는 목적이었다.
과거 백테스트를 안 하기로 했으므로 **그 목적이 사라졌다.**

남는 용도는 **음성 대조군** 하나다 — 전진 데이터(컷오프 이후)에 마스킹을 걸면
차이가 0에 수렴해야 정상이다. 여기서 차이가 나오면 마스킹이 룩어헤드가 아닌
다른 것을 깨뜨리고 있다는 뜻이다. 싸고(전진 데이터 재사용) 정보가 있다.

**뉴스 마스킹은 구조적으로 불완전하다**는 실측도 남긴다 — 1차 자료 4,000건 중
회사명 포함 83.6%(치환 가능), 명시적 시점 표지 23.1%(제거 가능). 그러나 사건 자체
(`버라이즌·6G·ISAC`)가 시점을 특정하므로 지울 수 없다.

## 5. 남는 실험 — 순서대로

### 5.1 노이즈 바닥 측정 (선행 필수, 하루 · 약 $2)

`temperature=0`이어도 결정론이 아니다. **같은 구성을 반복 실행해 `Var(A−B)`의 순수
잡음 수준을 먼저 알아야** "구성 A가 B보다 낫다"가 실재인지 판정된다.
기획서 6절의 "3회 이상 반복해 평균이 아니라 분산까지 보고"가 이것이다.

**이걸 안 하고 A/B를 돌리면 잡음을 실력으로 읽는다.**

### 5.3 다중 아암 + 요인 설계

탐색할 공간은 `{역할} × {프롬프트} × {데이터 종류} × {데이터 비중}`이다.
**절반 이상이 추가 호출 없이 탐색된다.**

| 차원 | 가짓수 | 방법 |
|---|---|---|
| 에이전트 조합 | 31 (5개 → 부분집합) | 기획서 9.1 무료 ablation — 개별 의견이 저장돼 있다 |
| 호라이즌 | 3 | 이미 구현 |
| 보유 규칙 | 2 | 이미 구현 |
| 확신도 임계 | 3 | 저장된 `confidence` 재계산 |
| 비중 방식 | 2 | `proposed_weight` |

→ **조합 1,116가지가 LLM 호출 0회**

새 호출이 필요한 차원은 **부분요인 설계**로 압축한다. 4요인 2수준이면
완전요인 16조합을 **8아암**으로 주효과 전부 추정.

모든 아암이 같은 `as_of`·같은 시장을 겪으므로 **완전 쌍대 비교**다.
다중검정 대가는 인정한다 — 8아암이면 Bonferroni로 `|t| > 2.73` 필요.
**개별 아암 순위가 아니라 요인의 주효과를 본다.**

## 6. 검정력 목표

| 목표 | 필요 조건 |
|---|---|
| IC = 0.05 검출 | 유니버스 300 → 시점 5회 / 유니버스 60 → 27회 |

| 레짐별 분해 | **달력이 상한이다.** 3종을 다 보려면 3년. 3개월 결과에는 "이 레짐에서"를 반드시 단다 |

**절대 성능 주장은 여전히 시간이 필요하다.** 유니버스 확대는 IC 측정 정밀도를 올릴
뿐, 레짐 다양성을 대체하지 못한다.

## 7. 하지 않는 것

- 백테스트 성적을 실전 기대수익으로 서술하지 않는다 (`CLAUDE.md` 4절)
- 과거 뉴스를 사서 백테스트하지 않는다 (4.1)
- 코스콤 테스트베드를 비교군으로 쓰지 않는다 (0절 — 평가 축이 다르다)
- 호라이즌을 표본 확보 수단으로 바꾸지 않는다 (4.3)
