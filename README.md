# MAS_TRADE

멀티 에이전트 LLM 주식 리서치 시스템. 미국장·한국장 각 1개 인스턴스로 운용한다.

**현재 단계:** 멀티 에이전트를 평가하기 위한 **토대를 먼저 세웠다.** 데이터 수집,
비교군(단일 LLM 호출 · 룰 기반), 시그널 채점, 자동 운영까지가 동작한다.
멀티 에이전트 레이어는 이 비교군을 **이겨야 채택한다** — 아래 [상태](#상태) 참고.

> **실계좌 주문을 실행하지 않는다.** 시그널 기록과 가상 보유 포트폴리오 추적만 한다.
> 이 저장소의 어떤 출력도 투자 자문이 아니다.

## 목표

수익률 극대화가 아니라 **다양한 관점의 구조화된 의견 생성과 그 검증**이다.
평가 단위는 포트폴리오 수익률이 아니라 **개별 시그널**이다. 3개월간 주 1회 리밸런싱이면
판단 시점이 12번뿐이라 표본이 부족하지만, 종목 15개 × 12회 = 180건의 시그널로 쪼개면
통계적으로 말할 수 있는 것이 생긴다.

전체 설계는 [`docs/plan.md`](docs/plan.md), 데이터 소스별 한도와 제약은
[`docs/data-sources.md`](docs/data-sources.md), 날짜별 결정·문제·해결 기록은
[`docs/journal/`](docs/journal/) 참고.

## 핵심 원칙

| 원칙 | 내용 |
|---|---|
| **계산은 코드, 해석은 LLM** | PER·변동성·상관계수·샤프 등 모든 수치는 `src/compute/`의 결정론적 코드가 계산한다. LLM은 주어진 수치를 해석·비교·판단만 한다 |
| **시점 정합성** | 그 시점에 실제로 알 수 있었던 값만 쓴다. 매크로는 ALFRED vintage, 재무는 공시 제출일, 뉴스는 발행 시각 기준 |
| **리스크 엔진은 거부권을 가진다** | LLM이 제안하고 룰 엔진이 승인/기각한다 |
| **전량 로깅** | 프롬프트·응답·데이터 스냅샷에 더해 **모델 버전·토큰·비용**까지 저장한다. 재현성의 전제이자 사후 ablation의 기반 |

## LLM

**DeepSeek 확정** (기획서 4절). OpenAI ChatCompletions 호환이라 벤더 교체는
`LLM_BASE_URL`·모델명 변경으로 끝나야 한다. 모든 호출은 `src/llm/`을 통한다.

| 단계 | 모델 | 모드 | 상태 |
|---|---|---|---|
| 단일 호출 베이스라인 | `deepseek-v4-pro` | thinking | ✅ 주 1회 운영 중 |
| 1차 스크리닝 | `deepseek-flash` | non-thinking | 설계 — `src/llm/`에 티어만 있고 호출부가 없다 |
| 분석 에이전트 · 논쟁 | `deepseek-v4-pro` | thinking | 설계 — 스키마만 |
| 리스크 판정 | **LLM 아님 — 룰 엔진** | — | 설계 — 스키마만 |

비용 규칙 세 가지:

- **프리픽스 캐싱** — 캐시 히트가 미스보다 모델에 따라 30~50배 싸다. 고정 프리픽스를 앞에, 종목별 가변부를 뒤에. `build_messages()`를 쓴다
- **오프피크 배치** — 피크는 UTC 월~금 01:00–04:00·06:00–10:00(= KST 10\~13시, 15\~19시). 그 외는 반값이므로 주간 배치는 KST 심야에 돌린다
- **모델 버전 기록** — 같은 별칭 뒤에서 모델이 갱신되면 전후 비교가 무효가 된다. 응답이 보고한 버전을 로그에 남기고, 버전 경계에서 성적을 섞지 않는다

## 데이터 소스

뉴스는 시장별로 소스가 다르다. US는 Finnhub `company-news`(분당 60콜), KR은 네이버 검색
API(일 2.5만 회 수준)가 메인이고, Alpha Vantage는 일 25회 한도라 **수집기가 아니라 센티먼트
베이스라인**으로만 쓴다. 한도가 곧 선택 기준인 이유는 과거 뉴스 아카이브를 살 수 없어 매일
수집해 직접 쌓기 때문이다 — 수집이 막힌 날의 구멍은 나중에 메울 수 없다.

발급 절차, 소스별 한도, 시점 정합 가능 여부는 [`docs/data-sources.md`](docs/data-sources.md).

## 구조

```
src/
├── data/      시점 정합 데이터 레이어 (US/KR 어댑터 + as-of 스냅샷)
├── compute/   결정론적 수치 계산 — LLM이 손대지 않는 영역
├── llm/       LLM 호출 레이어 (DeepSeek, 벤더 교체 가능 / 버전·비용 로깅)
├── agents/    단일 호출 베이스라인 · 컨텍스트 조립 · 출력 스키마 · 시그널 저장
│              (분석 에이전트 · 논쟁 · 리스크 엔진은 스키마만 — 미구현)
└── eval/      시그널 채점 · 룰 기반 비교군 · 벤치마크 · 가상 포트폴리오
scripts/       수집·측정·진단 CLI
docs/          기획서, 데이터 소스, 작업 일지
logs/          실행 로그 (git 추적 제외)
data/          mas_trade.sqlite3 + snapshots/raw/ (git 추적 제외)
```

## 수집

스케줄러는 한 시간마다 깨우기만 하고, 어떤 종목을 돌지는 마지막 수집 시각과 종목별 주기를
보고 코드가 고른다. 주기는 뉴스 유입 속도 실측으로 배정한다 (종목별 27배까지 차이 난다).

```bash
python scripts/collect_news.py --dry-run     # 대상만 확인
python scripts/collect_news.py               # 주기가 된 종목 수집
python scripts/collect_news.py --status      # 저장 현황과 열린 gap
python scripts/measure_news_rate.py --apply  # 유입 속도 재측정 후 주기 갱신
```

### 정기 실행

cron이 아니라 **launchd**로 건다(매시 5분 + 로그인 시). 노트북은 잠들고, cron은 자는
동안의 실행을 건너뛴 뒤 따라잡지 않는다. launchd는 깨어날 때 밀린 것을 한 번 실행한다.

```bash
scripts/install_scheduler.sh            # 등록 — 저장소를 옮긴 뒤에도 다시 돌리면 된다
scripts/install_scheduler.sh --status   # 등록 상태와 마지막 종료 코드
scripts/install_scheduler.sh --run-now  # 즉시 1회 실행 (검증용)
tail -f logs/collect.log                # 실행 결과
```

**저장소를 `~/Desktop`·`~/Documents`·`~/Downloads` 아래에 두면 안 된다.** macOS가 TCC로
보호하는 폴더라 launchd가 실행 자체를 거부한다(`Operation not permitted`, exit 126).
실측으로 확인했다 — `docs/journal/2026-09-16.md`.

수집 실패와 커버리지 미달은 예외가 아니라 gap으로 기록되어 다음 실행의 대상이 된다.
과거 뉴스는 나중에 살 수 없으므로 조용히 건너뛰는 것이 최악이다.

## 범위에서 제외

- **실계좌 주문 / 자동 매매** — 설계상 제외
- **Earnings Surprise** — 과거 시점 컨센서스 EPS는 기관용 유료 데이터라 조달 불가.
  실적 발표일 전후 주가 반응으로 대체한다
- **과거 뉴스 아카이브 백테스트** — 무료로 구할 수 없다. 지금부터 수집해 전진 검증으로만 평가
- **상장폐지 종목 포함 유니버스** — 유니버스를 시총 상위 고정 종목으로 좁혀 생존 편향을 회피

## 알려진 제약

- **DeepSeek는 학습 컷오프를 공시하지 않는다.** "컷오프 이후 구간만 백테스트" 규칙을 그대로
  적용할 수 없어, V4 프리뷰 공개일(2026-04-24) 이후를 보수적 대리 기준으로 쓰고 마스킹
  테스트를 병행한다. 백테스트는 프레임워크 비교용이지 성능 주장용이 아니다 (기획서 4.4절)
- **한국어 처리는 검증 전이다.** KR 인스턴스 착수 전에 DART 원문 독해·회계 표기·한자 혼입을
  따로 확인한다 (4.6절)

## 상태

**한 바퀴가 돈다.** 수집 → 지표 → 프롬프트 → LLM → 저장 → 채점의 전 경로가 동작하고,
launchd 작업 네 개(뉴스 매시 · 가격 일 1회 · 베이스라인 주 1회 · 점검 일 1회)가
사람 손 없이 돌린다.

### 지금까지의 성적 — 해석하지 않는다

```
KR  5거래일  채점 58/72  적중률 0.367[0.22,0.54]
US  5거래일  채점 55/70  적중률 0.467[0.30,0.64]
US 20거래일  채점 15/70  적중률 0.556[0.27,0.81]
```

**셋 다 신뢰구간이 0.5를 품는다 — 동전과 구분되지 않는다.** 이 숫자로 프롬프트를
고치지 않는다. 15종목 한 시점의 IC 잡음(±0.267)이 잡으려는 신호(0.05)의 **다섯 배**라,
지금 보이는 차이는 대부분 표본 운이다. 그래서 다음 단계는 프롬프트 개선이 아니라
**노이즈 바닥 측정과 유니버스 확대**다 ([`docs/validation.md`](docs/validation.md)).

측정보다 **측정 장치를 고치는 데** 시간이 더 들었다. 10월에만 조용한 고장 셋을 찾았다 —
종료코드 0이 멈춘 작업을 가린 것, 창 경계가 경고를 심각으로 부풀린 것,
macOS 알림이 한 달간 한 번도 뜨지 않은 것. 경위는 [`docs/journal/`](docs/journal/)에 있다.

이어서 작업할 때는 [`docs/HANDOFF.md`](docs/HANDOFF.md)를 먼저 본다 —
지금 상태, 다음 할 일, 알려진 고장, 건드리면 안 되는 설계 결정이 정리돼 있다.
